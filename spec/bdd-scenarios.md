# BDD-сценарії

## Керування категоріями

### BDD-001 — Створення та перегляд категорії

**Пов’язано:** `REQ-F-010`, `REQ-F-012`; `AC-010`, `AC-013`.

- **Given** у системі немає Category з назвою `Зарплата` типу `income`.
- **When** User створює Category з назвою `Зарплата` і типом `income`.
- **Then** система зберігає Category з унікальним незмінним Category ID та показує її назву і тип у списку Category.

### BDD-002 — Валідація категорії

**Пов’язано:** `REQ-F-011`, `REQ-NF-005`; `AC-011`, `AC-012`, `AC-030`.

- **Given** збережено Category `Їжа` типу `expense`.
- **When** User послідовно намагається створити Category з назвою лише з пробілів, Category `їжа` типу `expense` та Category `Їжа` типу `income`.
- **Then** система відхиляє назву з пробілів і дублікат у межах типу з повідомленням про порушене правило, але дозволяє однакову назву для типу `income`.

### BDD-003 — Перейменування категорії

**Пов’язано:** `REQ-F-013`; `AC-014`.

- **Given** збережено Category `Продукти` та пов’язану з нею Transaction.
- **When** User перейменовує Category на коректну назву `Харчування`.
- **Then** система зберігає нову назву в списку Category і показує її у пов’язаній Transaction, не змінюючи Category ID.

### BDD-004 — Видалення вільної та використаної категорій

**Пов’язано:** `REQ-F-014`; `AC-015`.

- **Given** Category `Подорожі` не використовується, а Category `Їжа` пов’язана з Transaction.
- **When** User намагається видалити обидві Category.
- **Then** система видаляє `Подорожі`, але відхиляє видалення `Їжа` та зберігає її разом із пов’язаною Transaction.

## Керування транзакціями

### BDD-005 — Створення коректної транзакції

**Пов’язано:** `REQ-F-002`, `REQ-F-003`, `REQ-F-004`, `REQ-F-005`, `REQ-F-006`, `REQ-F-007`; `AC-002`, `AC-003`, `AC-004`, `AC-005`, `AC-006`, `AC-007`.

- **Given** існує Category `Зарплата` типу `income`.
- **When** User створює Transaction типу `income` із додатним `amount`, минулою `date`, Category `Зарплата` та без `description`.
- **Then** система зберігає Transaction з унікальним незмінним Transaction ID і відображає її суму в UAH із двома знаками після десяткової крапки.

### BDD-006 — Відхилення некоректних даних транзакції

**Пов’язано:** `REQ-F-004`, `REQ-F-005`, `REQ-F-006`, `REQ-F-007`, `REQ-NF-005`; `AC-004`, `AC-005`, `AC-006`, `AC-007`, `AC-030`.

- **Given** існують Category типів `income` і `expense`, а решта обов’язкових даних Transaction може бути заповнена коректно.
- **When** User послідовно намагається зберегти Transaction з недодатним `amount`, надмірною десятковою точністю, майбутньою `date`, `description` понад 255 символів або Category невідповідного типу.
- **Then** система відхиляє кожну таку Transaction без зміни збережених даних і щоразу вказує поле та порушене правило.

### BDD-007 — Редагування транзакції

**Пов’язано:** `REQ-F-008`, `REQ-NF-005`; `AC-008`, `AC-030`.

- **Given** збережено Transaction із коректними даними.
- **When** User спочатку змінює її `amount` на інше коректне значення, а потім намагається змінити його на від’ємне.
- **Then** система зберігає коректну зміну без зміни Transaction ID, відхиляє некоректну зміну з повідомленням про помилку та залишає останній коректний `amount`.

### BDD-008 — Остаточне видалення транзакції

**Пов’язано:** `REQ-F-009`; `AC-009`.

- **Given** збережена Transaction відображається у Transaction List і враховується у фінансових показниках.
- **When** User видаляє цю Transaction.
- **Then** Transaction зникає зі списку та більше не враховується у фінансових показниках.

## Перегляд, фільтрація та показники

### BDD-009 — Відображення та типовий порядок списку транзакцій

**Пов’язано:** `REQ-F-015`, `REQ-F-016`; `AC-016`, `AC-017`.

- **Given** збережено кілька Transaction з різними датами, одна з яких має `description`.
- **When** User відкриває Transaction List без активних Filter.
- **Then** система показує Transaction від новіших до старіших із типом, сумою, датою, назвою Category та наявним описом, але без Transaction ID.

### BDD-010 — Фільтрація та некоректний діапазон дат

**Пов’язано:** `REQ-F-017`, `REQ-F-018`; `AC-018`, `AC-019`.

- **Given** збережено Transaction різних типів, Category та дат.
- **When** User застосовує Filter за Transaction Type, Category або коректним Date Range, а потім задає Date Range з початковою датою, пізнішою за кінцеву.
- **Then** коректний Filter залишає лише відповідні Transaction, а некоректний Date Range не застосовується і супроводжується інформаційним повідомленням.

### BDD-011 — Порожні стани списку транзакцій

**Пов’язано:** `REQ-F-019`, `REQ-F-020`; `AC-020`, `AC-021`.

- **Given** у системі немає збережених Transaction або жодна з наявних Transaction не відповідає активним Filter.
- **When** User переглядає Transaction List.
- **Then** система показує порожній список та інформаційне повідомлення відповідно про відсутність Transaction або результатів фільтрації.

### BDD-012 — Фінансові показники та їх незалежність від фільтрів

**Пов’язано:** `REQ-F-021`, `REQ-F-022`, `REQ-F-023`, `REQ-F-024`; `AC-022`, `AC-023`, `AC-024`, `AC-025`.

- **Given** загальна сума збережених Transaction типу `income` менша за загальну суму Transaction типу `expense`, а активний Filter приховує частину Transaction.
- **When** система відображає Total Income, Total Expenses і Current Balance.
- **Then** показники розраховуються за всіма збереженими Transaction незалежно від Filter, а Current Balance відображається як від’ємна різниця між Total Income і Total Expenses.

## Надійність і безпека

### BDD-013 — Збереження успішних змін після перезапуску

**Пов’язано:** `REQ-F-001`, `REQ-NF-001`; `AC-001`, `AC-026`.

- **Given** User успішно створив, змінив або видалив Transaction чи Category.
- **When** User штатно завершує та повторно запускає програму.
- **Then** система показує останній успішно збережений стан даних.

### BDD-014 — Цілісність даних після перерваної операції

**Пов’язано:** `REQ-NF-002`; `AC-027`.

- **Given** у системі є раніше збережені Transaction і Category.
- **When** операція зміни даних переривається до успішного завершення.
- **Then** система містить цілісний попередній або повністю новий стан без частково змінених записів, а інші дані залишаються без змін.

### BDD-015 — Помилка читання збережених даних

**Пов’язано:** `REQ-NF-003`; `AC-028`.

- **Given** збережені дані неможливо прочитати.
- **When** система намагається їх завантажити.
- **Then** система повідомляє User про помилку та не змінює ці дані.

### BDD-016 — Безпечна обробка текстового введення

**Пов’язано:** `REQ-NF-004`; `AC-029`.

- **Given** User вводить у текстове поле рядок із синтаксисом команди або програмного коду допустимої довжини.
- **When** система зберігає та відображає це значення.
- **Then** значення обробляється як звичайний текст, а команда або код не виконуються.
