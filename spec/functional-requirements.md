# Функціональні вимоги

## Загальні вимоги

- **REQ-F-001.** Система повинна зберігати дані Transaction і Category між запусками програми.
- **REQ-F-002.** Система повинна підтримувати для грошових сум лише валюту UAH і відображати суми з двома знаками після десяткової крапки.

## Керування транзакціями

- **REQ-F-003.** Система повинна дозволяти User створити Transaction із `type`, `amount`, `date`, `category` та необов’язковим `description`, присвоюючи їй унікальний незмінний Transaction ID.
- **REQ-F-004.** Система повинна приймати `type` Transaction лише зі значенням `income` або `expense`, а `amount` — лише зі значенням, більшим за нуль, і не більш як двома знаками після десяткової крапки.
- **REQ-F-005.** Система повинна вимагати `date` Transaction у форматі `YYYY-MM-DD` та відхиляти майбутню дату.
- **REQ-F-006.** Система повинна дозволяти відсутність `description` у Transaction і приймати його довжиною не більше 255 символів.
- **REQ-F-007.** Система повинна дозволяти призначити Transaction лише Category, тип якої відповідає `type` цієї Transaction, та відхиляти невідповідну комбінацію.
- **REQ-F-008.** Система повинна дозволяти User редагувати дані збереженої Transaction зі збереженням її Transaction ID та застосовувати до змінених даних правила перевірки, визначені для створення Transaction.
- **REQ-F-009.** Система повинна дозволяти User остаточно видалити Transaction.

## Керування категоріями

- **REQ-F-010.** Система повинна дозволяти User створити Category із назвою та типом, присвоюючи їй унікальний незмінний Category ID.
- **REQ-F-011.** Система повинна приймати тип Category лише зі значенням `income` або `expense`, вимагати її назву та приймати назву лише тоді, коли вона не складається тільки з пробілів, має довжину не більше 50 символів і є унікальною в межах типу без урахування регістру.
- **REQ-F-012.** Система повинна дозволяти User переглядати список Category.
- **REQ-F-013.** Система повинна дозволяти User перейменувати Category із застосуванням до нової назви правил перевірки, визначених для створення Category.
- **REQ-F-014.** Система повинна дозволяти User видалити Category, яку не використовує жодна Transaction, і забороняти видалення Category, яку використовує хоча б одна Transaction.

## Перегляд і фільтрація транзакцій

- **REQ-F-015.** Система повинна відображати Transaction List із типом, сумою, датою, назвою категорії та описом кожної Transaction за наявності опису, не показуючи Transaction ID.
- **REQ-F-016.** Система повинна за замовчуванням впорядковувати Transaction List за датою від новіших транзакцій до старіших.
- **REQ-F-017.** Система повинна дозволяти фільтрувати Transaction List за Transaction Type, Category та Date Range.
- **REQ-F-018.** Система не повинна застосовувати Date Range, у якому початкова дата пізніша за кінцеву, і повинна показувати інформаційне повідомлення про некоректний діапазон.
- **REQ-F-019.** За відсутності збережених Transaction система повинна відображати порожній Transaction List та інформаційне повідомлення.
- **REQ-F-020.** Якщо жодна Transaction не відповідає активним Filter, система повинна відображати порожній Transaction List та інформаційне повідомлення.

## Фінансові показники

- **REQ-F-021.** Система повинна обчислювати Total Income як суму `amount` усіх збережених Transaction типу `income`.
- **REQ-F-022.** Система повинна обчислювати Total Expenses як суму `amount` усіх збережених Transaction типу `expense`.
- **REQ-F-023.** Система повинна обчислювати Current Balance як різницю між Total Income і Total Expenses та допускати його від’ємне значення.
- **REQ-F-024.** Система повинна обчислювати Total Income, Total Expenses і Current Balance за всіма збереженими Transaction незалежно від активних Filter.
